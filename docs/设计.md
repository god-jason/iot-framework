## 1. 产品概述

### 1.1 定位

iot-os 是面向 MCU（以 STM32 为主，兼容 AVR 与 PC 模拟）的 **机器人 / 物联网固件平台**。它在裸机与完整操作系统之间提供一层薄而完整的能力：

- 一个可裁剪、默认静态分配的实时内核；
- 一套与厂商 HAL 解耦的外设抽象；
- 一组可直接复用的业务组件（网络、存储、升级、协议、机器人控制链路）。

设计目标不是做成通用 RTOS，而是让「换一颗 MCU 只需换平台层，业务代码零改动」。

### 1.2 核心价值

| 价值 | 实现方式 |
| --- | --- |
| 默认零动态内存 | 内核对象与缓冲区可由调用者静态提供，启动后内存占用可静态核算；另提供可选的动态对象接口 |
| 双端同源 | PC 模拟端与 MCU 端共用同一份业务代码，逻辑可在 Windows 上确定性回归 |
| 硬件解耦 | 业务只依赖 `hal_*` 与组件回调表，不直接触碰寄存器或厂商库 |
| 可裁剪 | 内核开关在 `iot_config.h`，外设开关在 `hal_config.h`，关闭即零代码 |
| 可验证 | 全仓库配套单元测试，单次回归 1 万+ 断言 |

### 1.3 典型使用者

- 需要快速搭建机器人控制固件的团队（差速底盘、机械臂、云台）；
- 需要 STM32 + 4G/以太网 + 云端对接的物联网设备；
- 需要在 PC 上先做算法验证、再平移到硬件的开发者；
- 教学与竞赛场景（结构清晰、可读、可裁）。

### 1.4 非目标

- 不做带 MMU 的通用操作系统；
- 不追求 SMP、文件系统、完整 POSIX；
- 内核默认不为对象申请堆内存；`iot_mem.h` 提供分配抽象，堆后端由平台实现（`vendor/tlsf`、`vendor/arena` 或 libc），并据此提供可选的 `iot_*_create()` / `iot_*_destroy()` 动态对象接口。

## 2. 总体架构

### 2.1 分层

```
┌──────────────────────────────────────────────────────────────┐
│  应用层   examples/demo.c   boards/<board>/main.c   用户业务   │
├──────────────────────────────────────────────────────────────┤
│  机器人控制链路   perception → localization → navigation      │
│                   → trajectory → drive → motor/servo/stepper  │
│  任务编排         planner / executor / action / behavior_bt   │
├──────────────────────────────────────────────────────────────┤
│  业务组件  components/  （40 个模块：协议、存储、升级、算法） │
├──────────────────────────────────────────────────────────────┤
│  实时内核  src/         任务 / 信号量 / 互斥量 / 队列 / 事件   │
│                          通知 / 定时器 / 调度 / 统计 / ISR     │
├──────────────────────────────────────────────────────────────┤
│  硬件抽象  hal/         35 个外设接口头（GPIO…ETH）           │
├──────────────────────────────────────────────────────────────┤
│  平台层    platforms/   pc / stm32(f1,f4,h7) / avr            │
├──────────────────────────────────────────────────────────────┤
│  第三方    vendor/      mongoose / cjson / tlsf / arena       │
├──────────────────────────────────────────────────────────────┤
│  网络      networks/    iot_net / iot_http / iot_mqtt + 后端   │
│  驱动      drivers/     50 个器件驱动                        │
│  启动升级  bootloader/  分区 / 镜像校验 / 升级 / 串口升级     │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 依赖规则

1. 上层可依赖下层，下层不得反向依赖。
2. `hal/` 不包含任何内核头、厂商头、组件头。
3. `components/` 不直接包含 `hal.h`（除少数需要总线的适配实现外），硬件访问通过回调表注入。
4. `drivers/` 通过 `drivers/common/driver_io.h` 统一访问总线，不直接调厂商 HAL。
5. `networks/` 只暴露 `iot_net.h` / `iot_http.h` / `iot_mqtt.h` 三个统一门面，后端可替换。

### 2.3 目录职责

| 目录 | 内容 | 规模 |
| --- | --- | --- |
| `src/` | 实时内核（`iot_*` 前缀，实现与测试同目录） | 17 个头 + 14 个实现 .c + 11 个测试 .c + 测试入口 |
| `hal/` | 外设抽象接口（`hal_*` 前缀） | 35 个头 |
| `components/` | 业务/算法组件 | 40 个模块 |
| `drivers/` | 器件驱动 | 50 个器件 |
| `networks/` | 网络门面与后端（eth / ml307） | 3 个门面 + 2 个后端 |
| `bootloader/` | 分区、镜像校验、升级、串口升级协议（平台无关） | 1 个模块 |
| `platforms/` | PC / STM32 / AVR 平台实现（含各自的 `*_bootloader.c` 移植层） | 3 套 |
| `boards/` | 具体板级工程（启动文件、链接脚本、main） | stm32f103c8 |
| `vendor/` | 第三方库（锁定版本，不修改） | 4 个 |
| `examples/` | 综合示例 | demo.c |

## 3. 实时内核（`src/`）

### 3.1 设计约束

- 纯 C99，默认静态分配（动态对象接口为可选路径）；
- 固定优先级抢占调度（数值越小越高），同优先级时间片轮转；
- 所有对象结构体公开，默认由调用者静态或栈上分配，也可用动态接口创建；
- tick 为 32 位毫秒计数，允许回绕，时间比较统一使用 `IOT_TICK_AFTER/BEFORE`；
- 中断上下文禁止调用阻塞 API，提供 `*_from_isr` 专用入口。

### 3.2 模块划分

| 模块 | 头文件 | 能力 |
| --- | --- | --- |
| 生命周期 | `iot.h` | `iot_init` / `iot_sched_start` / `iot_stop` |
| 任务 | `iot_task.h` | 创建、退出、让出、睡眠、优先级调整、任务通知 |
| 调度 | `iot_sched.h` | 就绪位图、选择、切换、抢占判定、`iot_sched_from_isr` |
| 等待队列 | `iot_wait.h` | O(1) 位图等待队列、阻塞/唤醒、优先级继承链 |
| 信号量 | `iot_sem.h` | 计数信号量，give 直接交接 |
| 互斥量 | `iot_mutex.h` | 所有权校验、递归优先级继承 |
| 队列 | `iot_queue.h` | 定长环形队列，阻塞收发，握手直传 |
| 流式缓冲 | `iot_sbuf.h` | 字节流环形缓冲，支持部分读写、阻塞与 FromISR 非阻塞访问 |
| 变长消息队列 | `iot_msgq.h` | 带长度头的环形消息缓冲，整条收发、不拆分消息 |
| 事件组 | `iot_event.h` | 32 位标志，ANY/ALL/CLEAR |
| 定时器 | `iot_timers.h` | 单次/周期软件定时器，默认由专用 `timer` 任务执行回调 |
| tick | `iot_tick.h` | tick 推进、延时链表 |
| 空闲 | `iot_idle.h` | 空闲任务、tickless 休眠 |
| 中断 | `iot_isr.h` | `in_isr`、FromISR 系列 |
| 统计 | `iot_stats.h` | 切换次数、任务运行 tick、栈水位 |
| 崩溃记录 | `iot_crash.h` | 异常现场记录、`.noinit` 持久化、文本化上报 |
| 内存 | `iot_mem.h` | 平台无关的 malloc/calloc/realloc/free，后端由平台提供 |
| 断言 | `iot_assert.h` | Debug 断言与故障定位 |
| 移植 | `iot_port.h` | 上下文切换、栈初始化、临界区、空闲、请求切换 |

### 3.3 编译期裁剪（`iot_config.h`）

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| `IOT_ASSERT_ENABLE` | 随 NDEBUG | 断言开关 |
| `IOT_TICK_HZ` | 1000 | tick 频率（`*_ms` 参数直接按 tick 计） |
| `IOT_USE_TIME_SLICING` | 1 | 同优先级时间片 |
| `IOT_TIME_SLICE_TICKS` | 1 | 时间片长度 |
| `IOT_USE_STACK_CHECK` | 1 | 栈底魔数校验 |
| `IOT_STACK_MAGIC` | 0xC0DEFACE | 魔数 |
| `IOT_USE_PRIORITY_INHERIT` | 1 | 互斥量优先级继承 |
| `IOT_SEM_MAX_COUNT` | 0x7FFFFFFF | 信号量上限 |
| `IOT_QUEUE_REQUIRE_POW2` | 0 | 队列深度限制为 2 的幂 |
| `IOT_USE_STATS` | 1 | 运行时统计 |
| `IOT_USE_EVENT` | 1 | 事件组 |
| `IOT_USE_NOTIFY` | 1 | 任务通知 |
| `IOT_USE_TICKLESS` | 1 | tickless 空闲 |

### 3.4 移植契约

平台实现必须提供：

| 接口 | 语义 |
| --- | --- |
| `iot_port_init` | 平台初始化（PC 端转换主线程为 Fiber） |
| `iot_port_stack_init` | 构造任务栈帧（Cortex-M 构造 PSP 异常帧） |
| `iot_port_start_first` | 启动第一个任务，通常不返回 |
| `iot_port_switch` | 保存 from、恢复 to |
| `iot_port_return` | 交还控制权（PC 端返回 main） |
| `iot_port_idle` | 空闲处理（PC 推进模拟时间 / MCU 执行 WFI） |
| `iot_port_idle_timeout` | 按最近截止点休眠（tickless） |
| `iot_port_request_switch` | 请求重调度（置位 PendSV） |
| `iot_port_critical_enter/exit` | 临界区，必须支持嵌套 |

关键约束：`iot_task_t` 的 `stack_ptr` 必须是结构体首成员（有编译期断言保护），Cortex-M 的 PendSV 汇编直接按偏移 0 取值。

### 3.5 中断模型

- 内核提供 `iot_sem_give_from_isr`、`iot_queue_send_from_isr`、`iot_event_set_from_isr`、`iot_task_notify_from_isr`；
- 均只唤醒不阻塞，`need_yield` 回传是否需要抢占；
- 唤醒高优先级任务时内核自动请求 PendSV，调用方通常无需再显式 yield；
- 在任务上下文误用阻塞 API 时，断言并返回 `IOT_FORBIDDEN_IN_ISR`。

## 4. 硬件抽象层（`hal/`）

### 4.1 接口清单

| 分类 | 头文件 |
| --- | --- |
| 基础 | `hal.h`、`hal_def.h`、`hal_config.h`、`hal_status.h`、`hal_handle.h`、`hal_macro.h` |
| 系统 | `hal_mcu.h`、`hal_clock.h`、`hal_pin.h`、`hal_pwr.h` |
| 数字 | `hal_gpio.h`、`hal_exti.h`、`hal_dma.h` |
| 总线 | `hal_uart.h`、`hal_spi.h`、`hal_i2c.h`、`hal_i2s.h`、`hal_can.h`、`hal_qspi.h`、`hal_sdio.h`、`hal_usb.h`、`hal_eth.h` |
| 模拟 | `hal_adc.h`、`hal_dac.h`、`hal_opamp.h` |
| 定时 | `hal_tim.h`、`hal_pwm.h`、`hal_capture.h` |
| 存储与安全 | `hal_flash.h`、`hal_crc.h`、`hal_rng.h`、`hal_rtc.h`、`hal_wdg.h` |

### 4.2 统一约定

- 所有接口返回 `int`：`HAL_OK`(0) 成功，负值为错误码（`HAL_BUSY` / `HAL_TIMEOUT` / `HAL_INVALID_PARAM` / `HAL_NOT_SUPPORTED` / `HAL_IO_ERROR` 等）；
- 句柄由调用者静态分配，`hal_handle_base_t base` 为每类句柄首成员；
- 未实现或被裁剪的模块仍可链接，运行时返回 `HAL_NOT_SUPPORTED`；
- 引脚使用逻辑编码 `HAL_PIN(port, pin)`，端口映射在平台层完成。

### 4.3 功能裁剪（`hal_config.h`）

按外设逐项开关：GPIO / EXTI / DMA / UART / SPI / I2C / I2S / CAN / ADC / DAC / OPAMP / TIM / PWM / CAPTURE / ENCODER / WDG / RTC / FLASH / CRC / RNG / PWR / QSPI / SDIO / USB / ETH。全部使用 `#ifndef` 包裹，可在编译选项中覆盖。

### 4.4 平台实现矩阵

| 平台 | 文件 | 说明 |
| --- | --- | --- |
| PC 模拟 | `platforms/pc/pc.c`、`pc_os.c`、`pc_uart.c`、`pc_rtos.c` | 外设用软件模型，UART 映射 stdin/stdout，内核用 Windows Fiber / POSIX ucontext（堆走 libc） |
| STM32F1 | `platforms/stm32/stm32_f1.c` | 基于 STM32Cube HAL，Cortex-M3 |
| STM32F4 | `platforms/stm32/stm32_f4.c` | Cortex-M4F |
| STM32H7 | `platforms/stm32/stm32_h7.c` | Cortex-M7 |
| AVR | `platforms/avr/avr.c`、`avr_os.c` | 8 位平台参考实现（堆走 libc） |
| 通用适配 | `platforms/stm32/stm32_os.c`、`stm32_mem_tlsf.c`、`stm32_rtos.c` | 时基/内存/内核移植 |

## 6. 机器人控制链路

### 6.1 数据流

```
传感器(编码器/IMU/测距)
        │
        ▼
  perception / encoder / imu         采样与预处理
        │
        ▼
  odometry  ──►  localization(EKF)   位姿估计
        │              ▲
        │              │ 绝对观测（激光匹配/二维码）
        ▼              │
  navigation(A*/D*) ───┘            全局路径
        │
        ▼
  trajectory(梯形/S曲线/插补)        速度与位置指令
        │
        ▼
  drive(位置环+速度环)               闭环控制
        │
        ▼
  motor / servo / stepper  ──►  HAL PWM/GPIO/TIM
        │
        ▼
  safety(限位/过流/急停)             全程旁路监控
```

### 6.2 建议任务划分

| 任务 | 优先级 | 周期 | 职责 |
| --- | --- | --- | --- |
| 安全监控 | 最高 | 1~5 ms | 读取急停/限位/过流，故障时立即停机 |
| 控制环 | 高 | 1 ms | `drive_update` + 编码器采样 |
| 里程计与定位 | 中高 | 5~10 ms | `odometry_update` + EKF 预测/更新 |
| 规划 | 中 | 事件驱动 | 路径求解、轨迹生成 |
| 通信 | 中低 | 10~50 ms | 协议收发、心跳、参数同步 |
| 日志/运维 | 低 | 空闲 | `alog` 落盘、shell |

### 6.3 控制环实现要点

1. 控制环由硬件定时器中断或高优先级任务驱动，不依赖内核 1 ms tick；
2. 编码器/ADC 用 DMA + 定时器触发，ISR 内只置标志或发通知；
3. ISR 到任务的数据传递使用 `iot_task_notify_from_isr` 或 `iot_queue_send_from_isr`；
4. 浮点运算放在任务上下文，避免在 ISR 内做长耗时计算；
5. 所有运动指令先过 `safety_motion_allowed`，故障时直接输出零。

## 7. 网络与云端

### 7.1 门面

| 头文件 | 能力 |
| --- | --- |
| `networks/iot_net.h` | TCP/UDP 连接、监听、收发、DNS、IP/MAC、时间 |
| `networks/iot_http.h` | HTTP 请求（GET/POST） |
| `networks/iot_mqtt.h` | MQTT 连接、订阅、发布、轮询 |

### 7.2 后端

| 后端 | 实现 | 适用 |
| --- | --- | --- |
| `networks/eth` | 基于 Mongoose，PC 与 MCU 以太网 | 有线网络、PC 模拟 |
| `networks/ml307` | 基于 AT 指令的 4G Cat.1 模组 | 蜂窝联网 |

切换后端只改编译宏（`IOT_NETWORK_ETH` 等），业务代码不变。

## 8. 启动、升级与部署

### 8.1 启动流程

```
上电 → Bootloader(bootloader/ 公共逻辑 + platforms/<plat> 移植层)
        ├─ boot_init          读 CONFIG 中的升级标志，初始化分区表
        ├─ boot_uart_wait_update  可选：串口等待升级请求并接收镜像
        ├─ boot_select_image  NORMAL / UPGRADE / RECOVERY / ROLLBACK
        ├─ boot_verify_image  镜像头 + 负载 CRC32 全量校验
        ├─ boot_install_image OTA → APP 擦写搬运并回读校验
        └─ boot_start_application  校验向量表后切栈跳转
                │
                ▼
        App: hal_init → iot_init → 创建任务 → iot_sched_start
```

### 8.2 分区与镜像

| 模块 | 职责 |
| --- | --- |
| `partition_*` | 分区表：Boot、App、OTA、参数区，读写擦除走 `hal_flash` |
| `image_*` | 镜像头、版本、长度、CRC32 校验 |
| `upgrade_*` | 升级状态机：擦除 OTA、接收、校验、就绪 |
| `boot_*` | 升级/回滚标志持久化、镜像安装与跳转 |
| `boot_uart_*` | 串口升级：握手帧、分块接收、逐块 CRC、整镜像校验 |
| `platforms/*_bootloader.c` | 移植层：Flash 读写擦除、SRAM 范围、向量表跳转、串口绑定 |
| `components/fota` | 下载、写入、校验、请求重启 |

默认 64KB Flash 布局：Boot 0x00000/16K、App 0x04000/28K、OTA 0x0B000/16K、
Config 0x0F000/4K，可用 `partition_register()` 覆盖。

升级失败可回滚到上一有效镜像；`boot_confirm_application` 用于「启动成功后确认」，避免反复回滚。
模块细节（移植契约、串口协议、镜像格式）见 `bootloader/README.md`。

### 8.3 板级工程

`boards/stm32f103c8/` 提供可烧录固件的完整要素：

| 文件 | 作用 |
| --- | --- |
| `startup_stm32f10x_md.S` | 启动文件与向量表 |
| `stm32f103c8.ld` | 链接脚本（Flash/RAM/栈布局） |
| `board.c/.h` | 时钟、引脚、外设初始化 |
| `main.c` | 应用入口 |
| `syscalls.c` | newlib 系统调用桩（`_write` 等） |

### 9.1 目标

### 9.2 关键机制

- `components/*` 的头文件路径由 `os.dirs()` 自动收集，新增组件无需改脚本；
- 非测试目标通过 `iot_exclude_tests()` 统一排除 `*_test.c` 与 `test_*.c`；
- STM32 交叉编译显式指定 `arm-none-eabi-*` 工具链，CPU/FPU 选项强制透传；
- 固件目标使用自定义启动文件与链接脚本，`-nostartfiles` + `nano.specs` 控制体积。

## 11. 资源与性能约束

| 项目 | 约束/现状 |
| --- | --- |
| 动态内存 | 默认 0 次 malloc；可选 `iot_*_create/destroy` + `tlsf` / `arena` 堆后端 |
| 内核代码量 | 约 3~5 KB（裁剪后更小） |
| 任务栈 | 由调用者指定，空闲任务默认 1 KB |
| tick 精度 | 1 ms，32 位回绕约 49.7 天 |
| 优先级 | 8 级，最低一级保留给空闲任务 |
| 队列/定时器 | 深度与数量由调用者静态定义 |
| 浮点 | 机器人算法使用 float，F4/H7 建议开启 FPU |

## 12. 已知限制

1. **单实例模块**：`navigation`、`motion`、`mapping` 使用静态工作区，同一时刻只允许一个搜索/解释器运行，非线程安全，需限定唯一 owner 任务。
2. **阻塞接口**：`stepper_move` 以循环发脉冲实现，会占用调用任务；高频场景建议改为定时器驱动的非阻塞状态机。
3. **planner 单计划**：同一时刻只有一个当前计划，`priority` 字段尚未参与调度。
4. **定时器回调上下文**：默认在专用 `timer` 任务中执行，可安全使用阻塞 API；`IOT_USE_TIMER_TASK=0` 时退回 tick 上下文，回调内禁止阻塞。
5. **tickless 未完全落地**：STM32 端 `iot_port_idle_timeout` 仍为 WFI，未按低功耗定时器重装并补偿 tick。
6. **驱动覆盖面**：50 个器件以传感器为主，电机驱动 IC（TB6612/A4988/TMC 系列）尚未内置，需按 `drive_ops_t` 自行适配。
7. **文档**：本文件为唯一现行设计文档，接口细节以头文件注释为准。

### 14.2 术语

| 术语 | 含义 |
| --- | --- |
| TCB | 任务控制块（`iot_task_t`） |
| 就绪位图 | 32 位整数，bit i 表示优先级 i 有就绪任务 |
| 直接交接 | give/unlock/send 时把资源直接交给等待者，避免入队再出队 |
| 栈水位 | 栈底连续保持魔数的字节数，用于估算剩余栈空间 |
| 优先级继承 | 高优先级任务等待锁时，临时提升持有者优先级，抑制优先级反转 |
| tickless | 空闲时跳过无意义的周期唤醒，按最近截止点休眠 |
| FOTA | 远程固件升级 |
| HIL | 硬件在环测试 |
